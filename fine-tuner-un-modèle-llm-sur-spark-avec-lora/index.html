Fine-tuner un modèle LLM sur Spark avec LoRA

1. Introduction

Le fine-tuning de grands modèles de langage (LLM) est devenu une pratique essentielle pour les développeurs et chercheurs en intelligence artificielle. Cependant, cette tâche exige généralement des ressources de calcul considérables, souvent inaccessibles en local. La NVIDIA DGX Spark change la donne en offrant une supercalculateur IA compact pouvant être installé sur votre bureau .

La DGX Spark, basée sur l’architecture NVIDIA Grace Blackwell, délivre jusqu’à 1 petaFLOP de performance IA et dispose de 128 Go de mémoire unifiée cohérente . Cette puissance permet aux développeurs d’exécuter localement des modèles d’IA pouvant atteindre 200 milliards de paramètres pour l’inférence et d’affiner des modèles jusqu’à 70 milliards de paramètres .

Dans cet article, nous allons explorer un processus complet de fine-tuning d’un LLM sur DGX Spark en utilisant PyTorch, la bibliothèque Hugging Face Transformers et les techniques d’adaptation efficaces en paramètres (PEFT) que sont LoRA et QLoRA .

2. Comprendre le fine-tuning d’un LLM

Le fine-tuning est le processus qui consiste à adapter un modèle pré-entraîné sur un vaste corpus de données générales à une tâche spécifique ou à un domaine particulier. Plutôt que de partir de zéro, coûteux en temps et en données, le fine-tuning utilise les connaissances déjà acquises par le modèle et les affine avec un ensemble de données plus ciblé .

Cette approche est particulièrement utile pour :

Enseigner des connaissances spécifiques à un domaine (documents techniques, données propriétaires)

Adapter le style et le ton du modèle à des cas d’usage particuliers

Améliorer les performances sur des tâches spécialisées

Principe LoRA fonctionne en geler les poids pré-entraînés du modèle et en introduisant de petites matrices de rang réduit entraînables dans chaque couche . L’équation devient :

text y = xW + x(AB) = x(W + AB) Où W est la matrice de poids gelée et A, B sont les matrices de faible rang entraînables.

Implémentation avec PEFT python from peft import LoraConfig, get_peft_model

lora_config = LoraConfig( r=8, # Rang des matrices d’adaptation lora_alpha=32, # Facteur d’échelle target_modules=[“q_proj”, “v_proj”, “k_proj”, “o_proj”], lora_dropout=0.1, bias=“none”, task_type=“CAUSAL_LM” )

model_lora = get_peft_model(model, lora_config) model_lora.print_trainable_parameters() # <1% des paramètres 11. QLoRA : entraînement quantifié QLoRA (Quantized LoRA) pousse l’optimisation mémoire plus loin en quantifiant les poids gelés du modèle .

Principales innovations QLoRA : Quantification 4-bit NF4 : type de données optimisé pour la distribution normale des poids

Double Quantification : quantification des constantes de quantification

Optimiseurs Paged : déchargement des états de l’optimiseur sur CPU

Implémentation avec bitsandbytes python from transformers import BitsAndBytesConfig from peft import LoraConfig, get_peft_model

bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_use_double_quant=True, bnb_4bit_quant_type=“nf4”, bnb_4bit_compute_dtype=torch.bfloat16 )

model = AutoModelForCausalLM.from_pretrained( model_name, quantization_config=bnb_config, device_map=“auto” )

qlora_config = LoraConfig( r=8, lora_alpha=16, target_modules=[“q_proj”, “v_proj”], lora_dropout=0.1, bias=“none”, )

model_qlora = get_peft_model(model, qlora_config) 12. Script complet d’entraînement Voici un script complet intégrant toutes les étapes précédentes :

python import torch from transformers import ( AutoTokenizer, AutoModelForCausalLM, TrainingArguments, Trainer, BitsAndBytesConfig ) from peft import LoraConfig, get_peft_model from datasets import load_dataset

1. Configuration

model_name = “meta-llama/Llama-3.2-3B” dataset_path = “./data/training_data.jsonl” output_dir = “./qlora-finetuned”

2. Quantification

bnb_config = BitsAndBytesConfig( load_in_4bit=True, bnb_4bit_use_double_quant=True, bnb_4bit_quant_type=“nf4”, bnb_4bit_compute_dtype=torch.bfloat16 )

3. Chargement du modèle

model = AutoModelForCausalLM.from_pretrained( model_name, quantization_config=bnb_config, device_map=“auto” ) tokenizer = AutoTokenizer.from_pretrained(model_name) tokenizer.pad_token = tokenizer.eos_token

4. Configuration LoRA

lora_config = LoraConfig( r=16, lora_alpha=32, target_modules=[“q_proj”, “v_proj”, “k_proj”, “o_proj”], lora_dropout=0.1, bias=“none”, task_type=“CAUSAL_LM” ) model = get_peft_model(model, lora_config)

5. Dataset

dataset = load_dataset(“json”, data_files=dataset_path)

def tokenize_function(examples): return tokenizer( examples[“prompt”] + " " + examples[“completion”], truncation=True, padding=“max_length”, max_length=512 )

tokenized_dataset = dataset.map(tokenize_function, batched=True)

6. Entraînement

training_args = TrainingArguments( output_dir=output_dir, per_device_train_batch_size=2, gradient_accumulation_steps=4, num_train_epochs=3, learning_rate=2e-4, fp16=True, logging_steps=10, save_strategy=“epoch”, save_total_limit=2, )

trainer = Trainer( model=model, args=training_args, train_dataset=tokenized_dataset[“train”], )

7. Lancement

trainer.train() 13. Lancement du training Pour lancer l’entraînement, exécutez simplement le script Python. La DGX Spark gérera automatiquement l’allocation mémoire et les calculs sur le GPU Blackwell.
